# Load library

The Injector tab loads a selected DLL into the process attached on the Memory tab. Use it only with processes and libraries you are authorized to inspect. Choose an absolute DLL path and confirm the displayed process name and PID before selecting **Load DLL**.

The DLL must match the target's x86 or x64 architecture. The x64 analyser supports both x64 targets and x86 targets; x86 targets use `MemoryAnalyserLoader32.exe`, which must be present beside the analyser executable. An x64 build automatically builds and copies the helper. The x86 analyser supports x86 targets only. The manually selected pointer size on the Memory tab does not determine the loader's architecture check.

Windows must permit the additional access needed to create a thread and write memory in the target. Protected processes, loader restrictions, incompatible dependencies, and DLL initialization failures can prevent loading; the panel reports the outcome where it can be determined. On an architecture mismatch, the panel reports the detected target machine, DLL machine, PE magic, and the path Windows opened. x86 is machine `0x014C` with PE32 magic `0x010B`; x64 is machine `0x8664` with PE32+ magic `0x020B`. Check the opened path as well as the selected path, particularly when Windows filesystem redirection or links are involved. Windows module enumeration may fail for extended-length paths, leaving the load outcome unknown.

Once started, the remote loader thread is monitored without blocking the UI; initial file validation can take time. Detaching does not cancel an in-progress load. If it takes too long, the result remains unknown and the operation continues to be monitored; do not retry while it is pending. Exiting the analyser cannot cancel a remote loader thread. If the helper is restricted by a Windows job, job shutdown can interrupt monitoring and leave the remote path buffer allocated until target exit. The feature does not unload DLLs or elevate privileges.
